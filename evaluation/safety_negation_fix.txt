SAFETY EXPLICIT MATCHER — NEGATION FIX — 2026-09-30
===================================================
Scope: app.py explicit_safety calculation only. No ML model, thresholds, high_risk list, crisis intent logic, final OR decision, response text, LIFF assessment, dataset, model artifact, or existing evaluation file was changed. This is rule behavior testing, not clinical validation.

1. OLD BEHAVIOR
---------------
handle_message() stripped the LINE message, lowercased it, and set explicit_safety=true whenever any of nine literal Thai phrases appeared anywhere in the message. It could not distinguish a clear denial, quotation, third-person report, or later contradictory clause. Any explicit_safety=true forced the crisis reply independently of the two ML checks.

2. NEW HELPER
-------------
app.py now defines detect_explicit_safety(text: str) -> bool. It keeps the original nine phrase literals and first performs the same substring check. If none matches, it returns false as before. If one matches, it checks a small, anchored clear-denial pattern over a whitespace-normalized whole statement; only a full match returns false. All other matches return true. The only new import is Python standard-library re; no dependency was added.

handle_message() now calls detect_explicit_safety(text). The final policy remains explicit_safety OR risk_is_high OR intent_is_crisis. Risk/intent labels, thresholds, inference call, and reply text are unchanged.

3. CLEAR NEGATION RULE AND MIXED HANDLING
-----------------------------------------
The anchored pattern recognizes short whole-message denials of อยากตาย, คิดฆ่าตัวตาย, or อยากทำร้ายตัวเอง with ไม่/ไม่ได้, optional ฉัน/ผม/หนู or ตอนนี้, and optional แล้ว. Trailing sentence punctuation is ignored only for this clear-denial comparison. Examples that now return false from the explicit rule include ไม่ได้อยากตาย, ฉันไม่ได้คิดฆ่าตัวตาย, ไม่ได้อยากทำร้ายตัวเอง, ตอนนี้ไม่ได้อยากตายแล้ว, and ไม่อยากตาย.

The pattern must match the WHOLE normalized statement. A later clause, admission, hopelessness, prior-risk context, double negation, quoted/informational text, or third-person report does not match this narrow exclusion and keeps the previous conservative true result. In particular, the four D/mixed test cases remain true. This helper returning false does not declare a user safe: risk_is_high or intent_is_crisis can still trigger the unchanged safety branch.

7. LIMITATIONS
--------------
- The exclusion intentionally covers only narrow whole-message denial patterns. Longer denials with explanatory text, double negations, third-person reports, quotations, and information questions can still trigger explicit safety. This preserves a conservative default but leaves five false positives in the synthetic matrix.
- The prior lexical gap A5 is unchanged. ML risk/intent might still catch it; this task did not run ML and makes no claim about overall system sensitivity.
- Removing a direct phrase trigger for a short denial does not itself determine clinical safety or prevent the independent ML checks from selecting the safety response. Human/safety review is still needed for real-world deployment behavior.
- The matrix is synthetic and small; before/after counts are not population error rates.
